# IOG script-flag analysis plan

Status: **DRAFT for approval** · Written 2026-10-31 · Companion file: [flag-analysis-prompts.md](flag-analysis-prompts.md) (agent prompts)

Goal: find, understand, name and document every **major script/game flag** used by the `extracted/**/*.asm` code of the Illusion of Gaia (US) baserom, store the result in a machine-readable registry that the Mesen2 MCP server and test harness can use, and split the work into iterations small enough for one agent session each.

## 2. What counts as a "script flag"

### 2.1 Index conventions

- **Global flag index** `n` (decimal in the registry, `$hex` in text): byte `$0A00 + (n >> 3)`, bit `n & 7`, mask `1 << (n & 7)`. Byte and word COP operands address the same array.
- **Helper bases** (`flag_helpers.asm`): `Raw` +`$0000` (index masked to 8 bits), `_0100`, `_0200`, `_0300`, `_0510` (each masks to 8 bits, then adds the base), `wramFlags` = the `$0400`-`$04FF` slice (global = WRAM-relative + `$0400`), `*_Offset100` (masks to 3 bits, lands at global `$0500`-`$0507`).
- COP sense byte: `BranchOnFlag* ( #id, #00, &X )` branches when the flag is **clear**, a nonzero sense when it is **set**. `WaitOnFlag*` yields until the flag matches the sense (rewinds `$00`, re-executes each frame).
- The helper-index table of the inventory (`$0100`-`$0107` for boss rewards) and the engine comments disagree on numbering only because of F3: always say which convention you use.

### 2.2 Domains

| Dom | Name | Global index | Bytes | Persistence | How it is accessed | Population in `extracted/` | Iteration |
|-----|------|--------------|-------|-------------|--------------------|----------------------------|-----------|
| D1 | **Scene scratch** | `$0000`-`$000F` | `$0A00`-`$0A01` | Zeroed by every `ClearSceneState`; saved/restored around the inventory overlay (F1) | COP `$CC`-`$D3`, `SetFlagRaw`/`TestFlagRaw`, direct `LDA $eventFlags` | 16 indices, 723 sites | per scene group (FL2x) |
| D2 | **Story / world events** | `$0010`-`$00FF` | `$0A02`-`$0A1F` | Save block | COP, `*Raw` helpers (actor-parameter indices: laborers `$A0-$A3`, necklace stones `$98/$99`, statues `$F8-$FD`, orbs `$F2/$F3`) | 202 literal indices, 837 sites | FL2x (single area), FL30/FL31 (spine) |
| D3 | **Event triggers / death actions** | `$0100`-`$01FF` | `$0A20`-`$0A3F` | Save block | COP word forms, `*_0100`, `event_blocks.ApplyAllEventBlocks` (flag `$0100+n` = event block n), enemy death-action index | 66 literal indices >= `$0100` (highest `$0185`; all are word-form COPs), 133 sites | FL11 |
| D4 | **Chests, hidden Red Jewels, barriers** | `$0200`-`$02FF` | `$0A40`-`$0A5F` | Save block | `*_0200` (`scene_chest_table` byte 3, hidden jewel actor parameter, barrier table) | table-driven | FL12 |
| D5 | **Scene clear reward** | `$0300`-`$03FF` | `$0A60`-`$0A7F` | Save block | `*_0300` (A = scene id) | table-driven (87 candidate scenes) | FL13 |
| D6 | **Dungeon kill flags** (`wramFlags`) | `$0400`-`$04FF` | `$0A80`-`$0A9F` | Zeroed on world-map entry, `st68_kara`, `sp58_red_eye`, game over | `SetWramFlag`, `CheckEnemyDefeatedFlag`, COP `$D8` (index = `enemyNum`) | table-driven (enemy numbers in `scene_actors`) | FL14 |
| D7 | **Boss reward / ability unlock** | `$0500`-`$0507`, `$0510`-`$059F` | `$0AA0`, `$0AA2`+ | Save block | `*_Offset100`, `TestFlag_0510` (`characterForm*4 + slot`); `$0AA2` is also `abilityBitmask` | table-driven | FL15 |

| D9 | **Scene-meta gates** | any flag, read from the scene data stream | n/a | n/a | `$13 <flag>` in `scene_meta` command streams (`SceneCmd_Branch`) | decoded in FL10 | FL10 |

The Mesen2 plan's actor flag bits (`$10`, `$12`, `displayModeFlags`, `playerFlags`) are **out of scope**.

### 2.3 "Major" flags

A flag is **major** (must have a full record) when any of these holds:

1. persistent (D2-D7) and referenced by at least one `BranchOnFlag*`/`WaitOnFlag*` that guards a spawn, door, dialog, reward, scene variant or boss;
2. used in two or more scene groups (spine);
3. engine-owned (system, title, boot, overlay, player, thinkers);
4. a D1 scratch flag that **synchronizes actors** (set then wait) or gates a cutscene stage;
5. any flag a scene needs before the player can move (scene entry).

Everything else (a scratch flag used by one actor as a private state bit) still gets a **row** (one line: scene, actor, role), not a full record. Baseline sizes (literal COP indices only):

| Tier | Definition | Indices | COP sites | Record level |
|------|-----------|--------:|----------:|--------------|
| T1 | Scratch `$00`-`$0F` | 16 | 723 | per (scene, index) rows; full record where it synchronizes actors |
| T2 | Persistent `< $100`, one area | 147 | 493 | full |
| T3 | Persistent `< $100`, two or more areas (spine) | 55 | 344 | full, written by FL31 |
| T4 | `>= $100` literals | 66 (59 single, 7 spine) | 133 | full, written by FL11-FL15 |
| T5 | Helper/table-addressed (D3-D7 without a literal) | bounded sets (for example 87 scene-reward flags, 46 chest flags, 253 kill flags) | n/a | table rows plus a domain record |

## 3. Deliverables and data model

### 3.1 Registry `db-us/flags.json` (schema draft; FL00 finalizes it with the user)

Keys are **decimal global indices** (the numbers that `scene-flags.json`, `run_recipe warp {flags}` and `iog.setEventFlag` already use).

```json
{
  "schema": 1,
  "domains": { "D1": { "name": "scene scratch", "range": [0, 15], "persistence": "scene" } },
  "flags": {
    "63": {
      "hex": "$003F", "address": "$0A07", "mask": "$80", "domain": "D2",
      "meanings": [
        {
          "scope": null,
          "name": "ec_lance_letter_shown",
          "summary": "Will showed Lance's letter to the Edward's Castle guard.",
          "stage": "act1.edward_castle",
          "kinds": ["quest-guard"],
          "grade": "VERIFIED-RUNTIME",
          "effects": { "set": "The guard actor lets the player move.", "clear": "The guard actor locks the joypad (joypadMaskStd $065A stays nonzero)." },
          "requires": [], "excludes": [], "pairsWith": [],
          "evidence": ["extracted/edward_castle/...:NN"],
          "runtime": { "result": "H3_20261029", "trial": "warp $0A with and without flag" },
          "notes": ""
        }
      ]
    },
    "1": {
      "hex": "$0001", "domain": "D1",
      "meanings": [
        { "scope": { "scenes": [33] }, "name": "ir_gold_tile_a", "summary": "...", "kinds": ["puzzle-state"], "grade": "VERIFIED-STATIC", "evidence": ["..."] },
        { "scope": { "scenes": [9, 10] }, "name": "...", "..." : "..." }
      ]
    }
  }
}
```

Rules:

- **`scope: null`** = the same meaning everywhere (all D2-D7 flags unless the index is reused). **`scope: {scenes:[ids]}`** (and optionally `actors:[...]`) for D1, and for any persistent index that is reused with a different meaning (record this as a finding).
- **Sites are not stored by hand.** The tool joins the FL01 inventory (ROM offset, file, line, opcode, role) to the registry by index and scope. Agents write analysis; the tool writes evidence tables.
- **`name`**: lower snake_case, unique per `(index, scope)` and unique across the registry for persistent flags. Pattern `<area>_<subject>_<state>`: area code = the letters of the scene prefix (`sc`, `ec`, `av`, `dm`, ...; engine flags use `sys`), state as `_seen`, `_done`, `_open`, `_given`, `_claimed`, `_active`; handshakes as `_req` / `_ack`. A name states what **is true when the flag is set**.
- **`kinds`** (controlled list): `once-latch` (test, skip, set after), `quest-guard` (spawn/skip gate), `quest-done`, `gate-open` (door, wall, bridge, tile), `handshake` (set then wait for clear, or the reverse), `cutscene-stage`, `puzzle-state`, `reward-claimed`, `form-latch`, `engine`, `idiom`, `unknown`.
- **`grade`**: `VERIFIED-RUNTIME` (A/B trial or census with a positive control, FR steps only), `VERIFIED-STATIC` (every reader and writer read; effect unambiguous in code), `INFERRED` (consistent with context; at least two independent pieces of evidence; says what is missing), `UNKNOWN` (sites listed, meaning not established). `CONTRADICTED` is a *verdict* recorded against a shipped note, not a grade.
- A flag whose name is only a guess from dialog text must say so in `notes` ("name from dialog `dialogstring_XXXXXX`").

### 3.2 `db-us/scene-flags.json` (extend, stay compatible)

Existing shape stays valid: `{ "<scene id>": { "flags": [n,...], "note", "source" } }`. FL00 teaches the exporter three optional fields: `"names": ["ec_lance_letter_shown"]` (checked against the registry), `"entry": "free" | "locked-until-flag" | "cutscene" | "unreachable"`, `"grade"`. `"flags"` keeps meaning *the minimum set that makes the player free on arrival*. FL32 proposes entries statically; FR40 verifies them at runtime; only verified entries ship with `"grade": "VERIFIED-RUNTIME"`.

### 3.3 `db-us/flag-presets.json`

Named story checkpoints so the harness can enter any part of the game in a consistent state:

```json
{ "schema": 1, "presets": { "after_edward_castle": {
    "after": "after_south_cape", "flags": [63, 33], "flagNames": ["ec_lance_letter_shown"],
    "items": [{"id": 8, "slot": 0}], "form": "Will", "gems": 0, "abilities": [],
    "grade": "INFERRED", "evidence": ["FL32 milestone M04"] } } }
```

Items, form and abilities come from FL40. FR50 replays each preset and upgrades its grade.

### 3.4 Exports and docs

`npm run flags -- export` writes `artifacts/flags.json` (flat list: index, name per scope, byte address, mask, domain, summary, grade) and `artifacts/flag-presets.json`. `npm run flags -- docs` writes `docs/flags/README.md` (domains, lifecycle table, how to read) plus one page per area group. Neither is written by an agent by hand.

### 3.5 Inline comments

Flag sites get comments through `npm run merge` only. Comment style (one line, present tense): `; flag $0063 ec_lance_letter_shown: set after the letter is shown` on the first site of each flag per file, and on every `BranchOnFlag*`/`WaitOnFlag*` whose branch meaning is not obvious. Specs are drafted per iteration (`plans/flags/results/specs/FLxx_notes.json`) and applied in the apply pass (section 7). Text rules: the Mesen2 plan §8.2 item 5 and `gaia-core/docs/notes-and-comments.md` §"Comment Authoring Guide".

### 3.6 Definition of done for one flag (a "full record")

1. Every site is classified: setter, clearer, branch reader (which way it branches), waiter, helper caller, table reference, direct read.
2. Lifecycle: initial value, who sets and clears and **when in the story**, lifetime (scene, save, world map), and what resets it.
3. Effect of set and of clear on each reader (spawn skipped, door opened, dialog variant, reward, scene variant).
4. A plain-language meaning and a registry name, with the dialog or scene context that supports it.
5. Relations: prerequisites (flags that must already be set), exclusions, pairs and handshakes, other scenes that read it.
6. Entry effect: whether any actor locks the player when it is clear (feeds `scene-flags.json`).
7. Grade with evidence (`file:line` plus the ROM offset); `INFERRED` and `UNKNOWN` carry a runtime-queue item that says exactly what trial would settle them.

## 4. Method for one analysis iteration

### 4.1 Roles, write scope, hard rules

- **Analysis agents** (FL10-FL41) read `extracted/` and write **only under `plans/flags/results/`**: report, registry fragment, specs, runtime queue.
- **Tooling agents** (FL00, FL01) may edit `src/`, `docs/`, `package.json` and create the empty `db-us/flags.json` skeleton, nothing else.
- **Runtime agents** (FR*) follow the Mesen2 plan hard rules (12.1) and write under `mesen2-results/`.
- **The apply pass** (section 7) is run by you, or by an agent you start explicitly. Only it touches `extracted/` notes, `db-us/`, `docs/flags/`.
- No git write command; the user commits. No throwaway script to edit notes, comments, names, `blocks.json`/`files.json`, or docs (`.cursor/rules/no-adhoc-scripts.mdc`). Read-only helpers that print analysis (an `rg` pipeline, a small query over the inventory JSON) are fine; keep a reusable one in `plans/flags/tools/` with a header saying it never writes elsewhere.
- Never run `npm run extract`, `extract:lt`, `rebuild`, or an un-dry-run `merge`/`names`/`flags` in an analysis step.

### 4.2 Steps (every FL iteration follows this order)

1. **Read the contract.** This plan §2-§4 and §5 (your row), `docs/cop/families/scene_flags.md`, `docs/code/bank00/event-flags.md`, `extracted/system/engine/flag_helpers.asm` header.
2. **Pull the assignment.** From the inventory, list the sites and indices of your directories or domain. Split them into **owned** (used only in your scope) and **spine** (also used elsewhere: you record the site roles and a *proposal*, FL31 writes the record). List your scene ids from `db-us/groups.json`.
3. **Build the scene map** for each scene: placement (`extracted/tables/scene_actors.asm` entries: which actors spawn, with which parameter and death-action index), thinkers (`scene_thinkers.asm`), warps (`scene_warps.asm`), chests (`scene_chest_table.asm`), scene-meta `$13` gates (`scene_meta.asm`). An actor that no scene places is dead code: say so and still classify its flags.
4. **Read each script in full**, not only the flag line. For every actor that touches a flag write its state machine in two or three sentences (what it does with the flag clear, with the flag set, what changes when it sets or clears). Read the dialog text next to the code (`dialogstring_XXXXXX` blocks in the same file) and use it for meaning and naming.
5. **Order by story time.** Use `docs/Walkthrough-KeyBlade999.txt` and `docs/ram_map.txt` as *hints*; code decides. Assign `stage` tags (`act1.south_cape`, `act1.edward_castle`, ... as FL32 defines them; until then use the scene group name).
6. **Trace across scenes.** For each of your flags, find readers and writers elsewhere (inventory sites by index; `rg` for word forms `#$00XX`; helper callers with a dynamic trace; table rows). Note index reuse (same index, different meaning).
7. **Write the records** (registry fragment) at the level of §2.3 and §3.6, with `grade` and `evidence`. Unknowns are written as `UNKNOWN` with what you tried, not omitted.
8. **Check against shipped text.** `rg` the notes, `docs/` and `extracted/` comments that mention your flags or scenes. Where text is wrong, quote it (`file:line`) and draft a merge spec (`plans/flags/results/specs/FLxx_notes.json`, format of `gaia-core/docs/notes-and-comments.md` §"Merge spec format"). Run `npm run merge -- <spec> --dry-run` (read-only; the only npm command allowed besides `npm run flags -- ... --dry-run/--check` once FL00 exists).
9. **Queue the runtime work.** For every `INFERRED`/`UNKNOWN` flag and every **spine** flag write one queue item (format 4.5). Say which state to start from, which flags to set, what to observe, and what result would confirm or refute.
10. **Report** (template 4.5) and the final message: counts per grade, shipped notes now wrong, new questions (text only), and the recommended next iteration.

### 4.3 Hazard checklist (check each before you write a record)

| # | Hazard | Rule |
|---|--------|------|
| 1 | Operand radix | `#11` is hex `$11`; word operands `#$017C` are hex; the registry key is decimal |
| 2 | Branch sense | `( #id, #01, &X )` jumps **when set**; `( #id, #00, &X )` jumps **when clear**. The dominant idiom `( #id, #00, &skip )` right before a spawn means "skip if the quest is not done"; read the target before you decide |
| 3 | Wait semantics | `WaitOnFlag* ( #id, #00 )` waits for **clear**; the waiting actor is the *consumer*, the actor that clears is the *producer*: a handshake needs both |
| 4 | Scratch flags | `$00`-`$0F` are cleared at every scene load (F1). A write in scene A is invisible in scene B. Never write a persistent meaning for them |
| 5 | Flag `$00` | `scene_flag_init` sets it in 26 scenes; the player sprite code calls it the "Shadow flag". Do not assume either; FL31 settles it |
| 6 | Helper bases | Add the base and convert WRAM-relative indices (F3) before you name a flag; `TestWramFlag_Offset100` masks to 3 bits |
| 7 | Dynamic indices | Actor-parameter, table and `enemyNum` indices need the caller trace (`scene_actors.asm` parameter, `actor_execution.asm` decode). Use the inventory traces, but verify the row you cite |
| 8 | Direct reads | `LDA $eventFlags` and similar read several flags at once (plate gate: bits 1-4; Rama: low byte equals `$FE`): list every bit |
| 9 | Absence | "Not read" / "not set" needs the search you ran (patterns and scope). Unobserved is never "free" or "unused" |
| 10 | Names | Labels change; cite **file:line and the ROM offset** (`; {n}` tag) of each site. If the tree is untagged, use the FL01 inventory offsets or ask the user to run `extract:lt` |
| 11 | Dead code | `extracted/unused/` and unplaced actors: classify, but never use them as evidence of intended behavior |
| 12 | Two builds | The original and the rebuilt ROM share flag logic; button remaps do not matter here. Runtime steps name the ROM tag |

### 4.4 Search recipes

```text
# every flag COP in a directory (literal indices)
rg -n "COP \[(Set|Clear|BranchOn|WaitOn)Flag(Byte|Word)\]" extracted/<dir>
# one index, byte and word forms
rg -n "Flag(Byte|Word)\] \( #(\$0*)?3F\b" extracted
# helper callers
rg -n "flag_helpers\.(Set|Test|Clear)" extracted
# direct array access
rg -n "\$(eventFlags|wramFlags)|LDA \$0A[0-9A-F]{2}|STA \$0A[0-9A-F]{2}" extracted --glob "*.asm"
# scene placement and gates
rg -n "<scene id or actor name>" extracted/tables/scene_actors.asm extracted/tables/scene_meta.asm
# the ROM offset of a site (tagged tree only)
rg -n "; \{<decimal offset>\}" extracted
```

### 4.5 Report, fragment and queue formats

**Report** `plans/flags/results/FLxx_<yyyymmdd>.md`:

```markdown
# FLxx <title>
Date / agent / model · Inputs: inventory id (source_sha256 or FL01 build id), extracted tree (git HEAD short, tagged|plain)
Scope: <dirs / domain>; scene ids; files read N of M; flag sites covered N of N
Coverage: table index | sites S/C/T/W | owned|spine|dynamic | decision
Records: table index | scope | name | kinds | grade | one-line summary
Scene notes: per scene, actors and the flags they use (state machines in 2-3 sentences)
Spine proposals: index | proposed name | roles in this scope | confidence
Contradictions: shipped text (file:line, quote) | what the code does | spec row
Runtime queue: N items (file)
Draft specs: paths + dry-run output (counts, rejected rows)
Counts: VERIFIED-STATIC / INFERRED / UNKNOWN / CONTRADICTED
New questions: text only
```

**Registry fragment** `plans/flags/results/registry/FLxx_registry.json`: the `flags` object of §3.1 restricted to your flags (spine flags go under `"proposals"` instead). Before FL00 ships, this is the contract; after, `npm run flags -- <fragment> --dry-run` validates it.

## 6. Mesen2 and harness integration

- **Flag setting** already works: `run_recipe warp {scene, flags[], quick}` and `iog.setEventFlag(id)`. The harness gains registry **names**: `artifacts/flags.json` lets Python (`a_common.py`) and Lua translate `"ec_lance_letter_shown"` to 63. Server-side name support is a request for `mesen2-mcp-enhancement-requests.md` (text only; do not edit the server).
- **Scene entry**: `scene-flags.json` entries (verified by FR40) are what `export scenes` publishes as `requiredFlags` and `requiredFlagBytes`; a harness warp should pass them by default.
- **Presets**: expanded client-side (flags, then items through `write_memory` on `$0AB4`-`$0AC3`, form `$0AD4`, abilities `$0AA2`), then a warp. State files follow the Mesen2 plan §5 naming; every preset state gets a `states-index.md` row with the flags written.
- **Controls**: every flag trial pairs a control run (flag untouched) with a forced run (flag toggled) from the same state; the standing positive control is scene `$0A` with and without flag 63. A trial with no observable difference is `INCONCLUSIVE`, not "no effect".
- **Hazards that apply**: write the flag array only in disposable states; do not write low DP (`$80`-`$82` collision pointer); set `sceneNext` last; flags `$00`-`$0F` cleared at scene load means a scratch flag must be set *after* the scene is loaded and its effect observed in the same scene.
- **Reuse**: A1/A2 harness code (`a_census.lua`, `scenario_a1_flag_census.py`) is the pattern for write-callback censuses; copy the approach, do not edit those files.

## 7. Apply pass (user-run, per phase)

1. Collect the fragments and specs of the finished iterations (`plans/flags/results/`).
2. `npm run flags -- <fragment> --dry-run`, review, apply; `npm run flags -- --check`.
3. For comments: `npm run merge -- <spec> --dry-run`, apply, `npm run extract:lt`, `npm run rebuild` (two commands), compare with the newest `GATE:` line in `audit-of-audit/ACTION_PLAN.md`, then `npm run extract`.
4. For names (if an iteration finds a mislabeled flag-handling routine): `npm run names -- <spec> --dry-run`, apply, `npm run names -- --check`.
5. `npm run flags -- export` and `npm run flags -- docs`; for scene entry: `npm run flags -- scene-flags <spec>` and `npm run export -- scenes`.
6. Append the iteration to the progress log (section 11) with the dry-run counts. Tell the user "Please commit when you're ready" with a suggested message. No agent commits.
