## 1. Answers

**What is D6?** `wramFlags`: flag `$0400 + enemy number` = byte `$0A80 + (n >> 3)`, bit `n AND 7`. Meaning of a set bit: "the enemy with this number has been defeated since the last reset". It is a per-enemy-slot kill latch, saved with the rest of `$0A00-$0BFB`. Grade VERIFIED-STATIC.

**Who writes it?** COP `$D8` (`SetDungeonKillFlag`, `cop_handlers_dungeon_switch.asm:17-24`): `TYX` (`{44162}`), read `$7F0022,X` (the actor's `enemyNum`), a zero low byte is ignored, else `JSR SetWramFlag` (`{44172}`). Four COP `$D8` sites:
- `StandardEnemyDefeatHandler.asm:87` `{56306}`: the default death script. It is entered by `HitStaggerResolveHit` (`hit_stagger_controller.asm:266-275`, `{55740}-{55746}`) and the two inline paths in `combat_collision.asm` (`{245392}-{245424}`, `{245815}-{245847}`) whenever a victim's HP reaches 0 and it has no death callback, and by `JumpFar` from 13 own scripts and from `EnemyDefeatDispatch`. It runs after the kill counters and a 3-tick wait, and only when `statsPtr` is not the first stats entry (`{56285}`-`{56294}`) and the boss bit `$0080` of `extendedFlags` is clear (`{56297}`-`{56304}`).
- `EnemyDefeatDispatch.asm:75` `{697510}` (`EnemyDefeatDispatch_CountKill`; `av6D_dive_bat` reaches it by `JumpFar`, `av6D_dive_bat.asm:106`; other users were not enumerated).
- `awB1_wall_walker.asm:526` `{770381}` and `pyCC_mystic_ball.asm:239` `{771937}`: inline copies of the death routine for every kill except the last (`enemiesRemaining = 1` goes through `StandardEnemyDefeatHandler`: `awB1_wall_walker.asm:250-254` `{769352}-{769360}`, `pyCC_mystic_ball.asm:187-190` `{771820}-{771828}`).
The two helpers `SetWramFlag` / `TestWramFlag` are only reached from `SetDungeonKillFlag` (`{44172}`); `TestWramFlag` has no caller (`CheckEnemyDefeatedFlag` repeats the logic inline).

**Who reads it?** (1) `CheckEnemyDefeatedFlag` at every enemy spawn with a nonzero number (`actor_execution.asm:993` `{249721}`, test at `:1196` `{250099}`). (2) `gw88_tomb_dark_space.asm:18` `{507380}`: `LDA $0A9F`, `AND #$00FF`, `CMP #$003F` (`{507383}`, `{507386}`): when the low byte equals `$3F`, i.e. numbers `$F8-$FD` all set and `$FE`, `$FF` clear, the actor runs `StageBgChange #74` / `ApplyBgChange` and sets event flag `$0174` (`{507392}`-`{507397}`). The six stone archers of scene `$88` (rows `#0C-#11`, `gw83_stone_archer4`) carry `$F8-$FD`: this is a puzzle that reads the kill bits. VERIFIED-STATIC for the mechanism; queued for a run (FL14-TOMB). Search scope for "no other reader": every `.asm` under `extracted/` for `wramFlags`, `$0A8x`/`$0A9x` literals, `SetWramFlag|TestWramFlag` and the `JSL flag_helpers.*Wram*` helpers; and every COP line with `Flag` and an operand `#$04xx` (no match; the `#$04xx` operands of `SpawnAfterAbsFlags` are positions, not flags).

**What happens at scene load for a set bit?** `InitActorFromSceneData` stores the number at `enemyNum` (`actor_execution.asm:991` `{249715}`), calls `CheckEnemyDefeatedFlag` (`:993` `{249721}`) and on carry set jumps to `AdvanceSceneDataAndFree` (`:995` `{249726}`): the 9-byte record is skipped, the actor slot is reused for the next record or freed, and the record's event-block tiles are swapped (`AdvanceSceneDataAndFree` `{249588}-{249626}`). `enemiesRemaining` is incremented only after the check (`:1005` `{249750}`), so a skipped enemy is not counted. An enemy of a scene with a kill bit set therefore never exists again until a reset. Record number 0 skips the check; 70 of 1317 enemy rows have number 0 and are never tracked (all rows of scenes `$1B`, `$1F`, `$55`, `$5C`, `$67`, `$8A`, `$DD`, `$E8`, `$E9`, `$EA`).

**Numbering and sharing.** 253 distinct nonzero numbers (`$01-$FE`); `$F7` and `$FF` have no spawn row; `$00` is the "untracked" marker. Each dungeon numbers its enemies from about `$01`, upward, one block per room (the table `scenes` command prints the ranges): within a dungeon the numbers are unique, with these exceptions: `$45` (Mu: `$61#0A` and `$64#03`, both `mu5F_cyclops` rows `{829828}` and `{830304}`; scene `$61` numbers `$40-$59`, scene `$64` numbers `$45-$76`, so killing either cyclops hides the other at its next spawn), and in the pyramid `$D9: $F4 x4, $F8 x2, $FA x5, $FB x4, $FD x6`, `$DB: $FE x2`, and the dark-lair scene `$F4: $03 x2` (male and female vampire). 241 of the 253 numbers appear in more than one scene, almost all because dungeons reuse the same low numbers. That is harmless only if the bits are reset between dungeons.
