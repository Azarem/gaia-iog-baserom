## 1. Answers

**Q1: what is an event block and who triggers it?** An event block is one 8-byte entry of `event_block_table` that copies a rectangle of map tiles (and collision, or the effect layer) from one place of a scene to another. Block `n` has three triggers that all use the same index `n`:

1. flag `$0100 + n`, scanned by `ApplyAllEventBlocks` at scene load and at inventory close;
2. COP `StageBgChange #n` + `ApplyBgChange` (102 sites, many of them with no flag at all);
3. the last operand of an enemy-spawn row (`deathActionIdx`): when that enemy is defeated, the handler sets flag `$0100 + n` and spawns the reveal effect, which runs `StageBgChangeFromDeathIdx` + `ApplyBgChange`.

**Q2: what does each block do and in which scene?** The last table of section 4 lists all 158 entries (`$00-$9D`) with scene, source and destination rectangles and the layer. For every one of the 42 death rows the scene of the block equals the scene of the enemy row. For literal sites the setter and the block are in different scenes in the spine cases only (Babel crystal gates, `$0185`, and the `item_use_system` setters of `$0106`, `$0113`, `$0138`).

**Q3: death-action indices.** The death-action table of section 4 maps 42 rows of `scene_actors.asm` (42 distinct indices, one row each) to enemy actor, enemy number and block. 37 of the indices are death-only; `$0116`, `$0132`, `$016A`, `$016B` and `$0173` are also tested or waited on by another actor (section 6).

**Q4: the literal sites.** Sections 4 and 5. The 135 inventory sites resolve to 67 indices: 57 hand-written records and 10 spine proposals, with no unresolved site. With the 37 death-only indices that makes 94 records and 10 proposals.

**Q5: indices with no use.** 8 block indices have a table entry and no trigger anywhere (`$0100`, `$0107`, `$0109`, `$0111`, `$013C`, `$0148`, `$0172`, `$018C`; section 8), and `$019E-$01FF` have neither a table entry nor a user. 46 indices have a block that is reachable only through `StageBgChange` (no flag, no death row).

## 2. Mechanism (all offsets are ROM, decimal)

| Step | Evidence |
|---|---|
| Table | `event_block_table.asm`, 158 entries of 8 bytes, entry `n` at `119758 + 8n` (the build asserts the scene byte of every entry against the ROM). Fields: scene, srcX, srcY, width, height, dstX, dstY, layer. Blocks `$06`, `$14`, `$20` are layer 1 (effect layer), all others layer 0 (map layer and collision). `$07` is an all-zero scene-0 placeholder. |
| Flag scan | `event_blocks.asm:81` (offset 172529) reads `$0A20,Y`; for every set bit `ApplyAllEventBlocks` (172521) calls `LookupEventBlock` (172899) which multiplies the index by 8 with no bound check and skips the entry when its scene byte differs from `sceneCurrent`. |
| Copy | `CopyEventBlockTiles` (172576) copies the source rectangle over the destination rectangle; the source stays unchanged. |
| When the scan runs | at scene load (after `InitCameraBounds`, before `SpawnSceneActors`) and at inventory close (`inventory_overlay.asm:232`, offset 192111). |
| Death path | `deathActionIdx` is stored from the last operand of the enemy-spawn row by `actor_execution`. On defeat `StandardEnemyDefeatHandler` (`hit_stagger_controller.asm:266`; `TestFlag_0100` at `StandardEnemyDefeatHandler.asm:119`, offset 56361; `SetFlag_0100` at line 122, offset 56371) tests `$0100 + idx`; when idx is non-zero and the flag is clear it sets the flag and spawns `SpawnFieldRevealEffect` (child flags `$0342`), which runs COP #34 `StageBgChangeFromDeathIdx` and `ApplyBgChange`. |
| Other enemy handlers | `EnemyDefeatDispatch.asm:88/91` (offsets 697534/697544) is a callback used by a few enemies and jumps to the standard handler for the last enemy of a group; `awB1_wall_walker.asm:535/538` (770400/770410) and `pyCC_mystic_ball.asm:248/251` (771956/771966) carry their own copy of the same test-set-spawn code; `sg55`, `mu67`, `gw8A`, `pyDD`, `ir29` test D7 flags next to it (section 10). |
| Spawn-time re-apply | `CheckEnemyDefeatedFlag` applies the block at spawn when the D6 kill flag (`$0400 + enemyNum`) of a re-spawned enemy is set, so a defeated enemy's room keeps its opening without scanning `$0100 + idx`. |
| Gaps | An index `n >= 158` would read past the table. No setter of `$019E-$01FF` exists (section 8). |

## 3. Sizing statement

The guideline is about 60 indices; this iteration covers 158 block indices (94 records, 10 spine proposals, 46 block-only indices, 8 no-use rows) plus the range `$019E-$01FF`. All of them were covered, because the block table is one structure and splitting it would have hidden the index reuses. The death-only records (37) are generated from decoded `scene_actors` rows and are VERIFIED-STATIC for the row, enemy and block, but their tile effect is not decoded (their notes say so).
