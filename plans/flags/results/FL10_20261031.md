## 1. Answers

**Q1 (reset of `$0A00-$0AB3`).** Everything is zero after boot; `ClearSceneState` zeroes flags `$0000-$000F` and nothing else. Width evidence: the call site runs `SEP #$20` and then `JSL ClearSceneState` (scene_lifecycle.asm:230-231, offsets 252505 / 252507), so M=1 and X is untouched (16-bit, the engine default). The routine opens with `LDX #$0000`, encoded `a2 00 00` (3 bytes, offset 253273; ROM bytes read). A 3-byte `LDX #imm` decodes only with X=16-bit: with X=8-bit the CPU would take `a2 00` and then execute `00 8e` (`BRK`), so the code stream proves X=16-bit. The next instruction is `STX $eventFlags` (`8e 00 0a`, offset 253291), a 16-bit store: it writes `$0A00` and `$0A01` and nothing else, which is flags `$0000-$000F`. M (8-bit at the call site) does not matter for an index-register store; the later `LDA #$00` / `STA $backdropColors` (253382-253384) rely on M=1. The `DEX` that follows the list (253378) makes `X = $FFFF` for `invincibilityTimer`, again 16-bit. No `overrides.json` M/X entry is involved. Full table in section 4.

**Q2 (byte map).** Section 5. The flag array does not stop at `$0AB3` in practice: the last byte with a flag use is `$0AA3` (flag `$051F`; `abilityBitmask`). `$0AA4-$0AB3` hold four 16-bit state words plus unassigned bytes. `$0AB4` starts `inventorySlots` (save_system.asm header, wram-memory-map §2.8).

**Q3 (scene-meta gates).** Section 6, 18 of 18 gates, nine flags, all D2, all read with `TestFlagRaw` (index masked to a byte).

**Q4 (direct sites).** Section 7.

**Q5 (helper semantics).** Section 8.
