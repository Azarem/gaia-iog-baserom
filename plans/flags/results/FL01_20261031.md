## Design notes

- **Offsets.** Each instruction line carries `; {n}`; the site offset is that number. Verified against `rebuilt/Illusion of Gaia.smc`: all 1693 COP offsets hold byte `$02`, all 57 helper-call offsets hold `JSR`/`JSL`, all 18 gate offsets hold `$13` followed by the flag. The tool refuses to run on an untagged tree and refuses a site without a tag.
- **Scene-meta gates.** `scene_meta` is untagged data. Offsets are computed from the original record layout (`[id word][commands][$00]` from the `blocks.json` start); the computed end must equal the block end (it does, 897023; the tool warns otherwise). Scenes reaching a gate: linear flow from the scene's record in `scene_meta_list`, following `jump` and the label of a set-branch.
- **Scene ids** come from `scene_actors` placement (thinkers, enemy and actor spawns, reference `@stem.label`), then the directory scene key of `db-us/groups.json`, then the file-name prefix. Of the 1693 COP sites, 1611 come from placement, 72 from the directory key, 10 have no scene (8 files: `unused/*`, `prologue/pr_thinkers.asm`, `actors/player_transition_handlers.asm`, `actors/player/shadow_shimmer.asm`, `system/engine/scene_lifecycle.asm`); `files_without_scenes` lists the 41 files (249 sites, mostly engine code reached from every scene).
- **Indices.** Global `n`; `wram` is the wramFlags-relative index (global = relative + `$0400`); `_Offset100` helpers give global `$0500 + (A & 7)`.
- **Determinism.** Fixed order, no timestamps, hash of the tree recorded; a second run reports `same` for all three files.

## Deviations and caveats

- Roles: the list of the brief plus **`direct write`** for direct stores (`direct read` alone would hide 329 writes). `table reference` is in the role list but no site uses it: table-driven flags are trace candidates, not sites.
- `SetDungeonKillFlag` is counted but has no index per site (operand = enemy number); the enemy numbers are the candidates of `dungeon_kill_wram_flags`.
- `tagged_files` is 818 of 909: the other 91 files contain no instruction (data/tables); the tool would stop if any scanned site lacked a tag.
- One warning remains and is benign: `cop_handlers_hdma_dma.asm:106` reads `flag_helpers.bitmasks_bit_position` (a bit-position table used by HDMA code, not a flag call).
- `npm run type-check` is **not clean on this machine for reasons outside FL01**: `node_modules/@types` is absent (143 errors, `console`, `fs`, `path` not found, in every `src/*.ts`) and `allowImportingTsExtensions` is not set (TS5097 on every `./x.ts` import, as in `index.ts`, `export.ts`, `merge.ts`). With the node types of a sibling repo (`tsc --noEmit -p tsconfig.json --typeRoots <repo>/node_modules/@types --types node`) `src/flag-inventory.ts` has **no errors**; the remaining errors are the TS5097 on the `.ts` imports (one more now, `flags.ts` -> `flag-inventory.ts`, same convention as the rest) and two `string | undefined` in `src/index.ts` (not touched here). Fixing it needs `npm i -D @types/node` and a tsconfig change, which are outside what a tooling iteration may edit.
