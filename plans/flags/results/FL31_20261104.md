## `$FF`: all 38 sites

The flag is the byte `$0A1F` bit 7. It is clear after the engine's direct clear and set again by the engine before thinkers get a chance to run in the main loop.

Protocol (derived from the 38 sites and the two direct clears):

1. Only the engine clears it, with direct writes that are not COP sites: `scene_lifecycle.asm:842`/`:844` {253418}/{253423} and `inventory_overlay.asm:131`/`:133` {191814}/{191819}. The inventory has 0 `ClearFlagByte`/`ClearFlagWord` sites with operand `$FF`, and ClearEventFlag is called only by the COP handlers (search: the 909 extracted files, `rg` for the index in byte and word forms plus the inventory's `direct_accesses` list for `$0A00`-`$0A3F`; helper calls with a computed index take no literal).
2. The engine sets it at `scene_lifecycle.asm:886` {253564} (scene setup) and `inventory_overlay.asm:255` {192190} (overlay close).
3. Thinkers whose state the rebuild destroys test it. Pattern A (12 placed thinker files plus the unplaced `native_village_dup_unused`): init, `SetEntryHereAndYield`, branch back to init while the flag is clear, so they re-initialise HDMA tables or PPU registers. Pattern B (5 placed palette loops plus the unplaced `palette_buffer_clear_unused`): set the flag themselves, then `WaitOnFlagByte(FF, clear)`, so the palette bundle replays. `palace_fountain_palette` is a hybrid.
4. The wake happens once per inventory close. `RestoreGameState` restores the saved thinker list, `ResetThinkerWaitCounters` ({192179}) zeroes the wait counters, and the first `UpdateFrameRender` ({192186}; `system_core.asm:308`) runs `RunThinkers_Hdma_Light` and `RunThinkers_General_Light` while `$FF` is still clear. The set at {192190} comes after that frame. A scene setup cannot wake pattern B: the thinker list is built by `SpawnSceneThinkers` ({251879}) after the clear at {253418}, and the scene-start passes at {253549}/{253553} come before the set at {253564}.
5. Meaning: "scene setup is complete and the thinkers' state was not rebuilt since" (the flag is true from scene setup until the next inventory open). The name is `sys_scene_setup_done`, kinds `engine`, `handshake`.

Decision, one flag or a convention: it is one flag with one meaning. All 38 sites test or set the same engine state; no actor uses the clear state for a story fact (no site is in a file that is a story actor; the two set sites outside thinker files are the engine's own). The shipped palette-thinker notes described "next scene setup or inventory open" as the wake; the first half is wrong, which is a contradiction (below).

Ordering question (self-set versus a later tester in the same pass): the only scenes in which one file sets and a different file tests are `$5C` (`palace_coffin_hdma_table` sets, `sine_hdma_dual_channel` tests; `thinker_spawn_0CE96F`, `tables/scene_thinkers.asm:527-533`, lists the coffin thinker first) and `$E8` (testers only). The coffin thinker sets the flag one tick after its init (`SetFlagByte` at {48753} follows `SetEntryHereAndYield`), so in the pass that finds the flag clear it re-initialises without setting, and the engine's own set at {192190} (or {253564}) comes before its next tick. A thinker therefore cannot hide a clear from a later thinker in the same pass. This is `VERIFIED-STATIC` from the files read; no runtime confirmation (queue FL31-01 observes the whole wake).
