Corrections for R-I048-5 (to apply in a later iteration that touches those files):

1. `docs/code/bank00/actors-player-rewards.md` lines 220-266 (`statue_inventory_reward`): the table has 4-byte entries (flag, sprite, match, one tail byte), not "6x3 bytes"; 8 sparkle actors (not 6); the confetti is 60 bursts of which about 15 are visible; `$0676` is the high byte and bank of graphics cache slot D (`srcCacheBgD+1`), not "PPU scroll state"; `ComposeDigitSprites_AtCursor` is not included by the file (it includes `ApplyOrbitalOffsetFromRef`, `flag_helpers`, `inventory_spritemap`, `music_actors`, `sprite_composition`, `spriteset_enemies`); the actor does not run "when the player selects an uncollected slot": it runs in scene `$FD`, entered through `QueueMapChange` from six boss / event scripts; the exit sets exit effect 2 / enter effect 0 and speed 3 (the doc's "fade mode `$0303`" is only the speed word).
2. `docs/structs-reference.md` line 952: the statue table maps flag + sprite + match value, not "flag + item + slot".
3. `docs/code/bank0B-late-bosses-system-cutscene-actors.md` line 470 (`dialog_string_scanner`): it scans for the COP `PrintDialogString` call (bytes `02 BF`), not for a "marker"; the bank counter is 16-bit and starts at `$85` (banks `$85`-`$FF`, then `$00`-`$FF`), not `$85`-`$8C`; a string is shown only for operands at least `0x8000`.
4. `docs/code/bank02/README.md` line 382 and `extracted/actors/player/player_character.asm` line 107 (comment): "SpawnLastRel" is the raw instruction `COP SpawnListAppend` (flags `$2800`). `extracted/system/inventory/inventory_mgmt.asm` line 101 uses the same wording for a different spawn; check there as well.
5. `docs/cop/families/actor_spawn.md` line 673 already shows `SpawnListAppend` for the shimmer; no change.
6. `docs/code/bank02/player-character.md` / `docs/code/README.md` line 292 ("Five-Actor Player Architecture: ... `shadow_shimmer`"): the in-list order is attack, player, slope, controller and the shimmer is appended at the list end (`SpawnListAppend`); the sequence in that line is not the execution order.
