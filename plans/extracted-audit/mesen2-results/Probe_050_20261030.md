ROM: O (`rebuilt/Illusion of Gaia.smc`, SHA-1 `38de0c84dd2bc3bdfc0a3d7ab0220c79b70887c3`) for every row; R-plain (`rebuilt/Illusion of Gaia - Rebuilt.smc`, SHA-1 `795c7a8cb8924766d5c378ac1d92364d127e1d2a`, built 2026-10-29 16:32, older than the newest `extracted/` edits) for the matrix, B2 and `compare_runs` rows only.

Server: `C:\Work\mesen2-mcp\McpHost\bin\Release\net8.0\MesenMcpHost.dll`, 0.5.0 (repo HEAD d382e415, DLL built 2026-10-30 00:23), Mesen 2.1.0, 81 tools, `self_test` 17/17. Driven by `harness/mcp_client.py` (the Cursor namespace `user-mesen2-mcp-dev` was still the 0.4.0 process; T-30).

Script: `harness/probe_050.py` (sessions 1 to 5, about 50 s) and `harness/phase0_matrix.py`. Raw data: `raw/probe_050_20261030.json`, `raw/phase0_matrix_20261030.json`.

Positive controls: each fixed behaviour was checked against its 0.4.0 symptom (rewind: distance and SPC callbacks; offsets: `kit.wramOffset`; quick warp: from the title; JSON shapes: parsed by the client without the old text fallbacks). The B2 scenario was re-run on both ROMs and is **bit-identical** to the 0.4.0 data (determinism control).

Coverage: single session per row, no repeat of the timing rows (rewind 4.7 to 9 s varies with history). The hard watchdog (120 s) was **not** exercised: nothing hung; only the soft `timeoutMs` path was.

## Defects and surprises (T-20 to T-30, requests MCP-31 to MCP-42)

| ID | Pri | Summary |
|----|-----|---------|
| T-20 | **P0** | `--mcp-rom` writes a `Content-Length`-framed notification before the first request, glued to the `initialize` reply: line-based clients hang. Worked around in `mcp_client.py`. |
| T-21 | P1 | Offsets in `get_breakpoint_hits` are CPU aliases (`wramOffset 8456684`); only `pcPrgOffset` is right. |
| T-27 | P1 | No argument validation: `frames:"ten"`, 0 and -5 advance 1 frame; `write_word 70000` wraps to `0x1170`; byte 300 clamps to 255; unknown `set_cpu_state` keys, `start > end` and a bad count condition accepted. |
| T-24 | P1 | Script syntax and runtime errors are not flagged (`isError:false`, `stopReason:done`); a runtime error repeats every frame. |
| T-23 | P2 | `revert_rom_changes` undoes WRAM writes too. |
| T-22 | P2 | Missing state file/slot or both state flags kill the host silently; missing lib dir ignored without warning; `startupWarning` only in `get_rom_info`. |
| T-25 | P2 | `get_server_status` is answered only after the running call ends. |
| T-26 | P2 | Absolute paths accepted by `dump_memory`, `take_screenshot`, `save_state_file` (probe files cleaned up); `dofile`/`loadfile` are disabled. |
| T-28 | P2 | `rewind` correct but 4.7 to 9 s. |
| T-29 | P2 | `get_access_summary {start, length}` reads one byte; unknown `label` returns an error row (the root of the phase-3 T-15 misreading). |
| T-30 | P3 | Stale `win-x64` DLL and two registrations on it; Cursor still runs 0.4.0 until MCP is reloaded. |

## Not explained

- After a `rewind` the SPC exec callback count was 5,586 in the matrix (8 frames) against 7,001 in a clean session. In the probe session after `rewind` it gave 7,001. The difference between the two sessions has not been explained (the matrix ran the rewind after 600 frames of mixed calls); treat the SPC callback count after a rewind as unconfirmed.
- Quick warp to `$08` and `$0A` without flag 63 leaves the joypad locked (`0xCFF0`) while the recipe returns `ok:true`; whether a church or Seth dialogue is running was judged from screenshots only (`raw/screenshots/H3_scene_*.png`).

## Actions for the user

1. Reload MCP in Cursor so the `user-mesen2-mcp-dev` namespace runs 0.5.0 (look for `get_server_status`).
2. Point `mesen2-mcp` and `mesen2-mcp-rebuilt` at `net8.0\MesenMcpHost.dll` (or delete them) and drop `--mcp-rom` from the latter (T-20, T-30).
3. Run `npm run rebuild` so R-plain is current (B-05), then `npm run export -- labels`.
