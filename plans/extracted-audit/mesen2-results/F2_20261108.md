- Field that "holds the frame pointer" (`docs/code/bank00/data-tables-memory.md` §3.1, §3.2; `extracted/system/engine/sprite_composition.asm:885-973` `UpdateActorAnimation`): there is no per-actor frame-list pointer. The engine reads DBR = `$7F:0008,X` (sprite bank), the table word at `$7F:0006,X + 2 * $28`, the frame record at that word + `4 * $2A`, and writes group + 4 to `$7F:000C,X` (metasprite pointer). The set address is therefore reached through the table word. Two ways to select it were run (below): `$28` = `$4B`, and the table pointer `$7F:0006,X` moved by `2 * $4B` with `$28` = 0 (the word at row 0 of the moved table is then the set address `$86AE` itself).

## Script

Module `kit/lib/f2_kit.lua` (201 lines, SHA-1 `b27198261b58521e657be561a0d60070c7aece62`; requires `mesen_kit`, `iog_kit`, `gaia_kit`, `f1_kit`; it uses `f1.grab`, `f1.encode`, `f1.sheet`, `f1.romOff`, `f1.anim` of the F1 module). The call, `run_script` with `includes ["f2_kit"]`, `turbo true`, `frames 1200`, name `f2_run`:

```lua
f2.run{ name='f2', form=1, scene=0x01, settle=300, hold=8, crop={88,56,128,112}, scale=2, idx=0x4B }
```

The H1 check script (`f2_h1`, `includes ["gaia_kit"]`, 120 frames):

```lua
local c=0
emu.addMemoryCallback(function(a) if (a & 0xFFFF)==0x36 then c=c+1 end end, emu.callbackType.write, 0x36, 0x36, emu.cpuType.snes, emu.memType.snesWorkRam)
local n=0
kit.onFrame(function() n=n+1 if n==119 then local s=emu.getState(); kit.finish({k=s['cpu.k'], sp=s['cpu.sp'], pc=s['cpu.pc'], scene=kit.r16(0x0644), ctl36=c, frames=n, form=kit.r16(0x0AD4)}) end end)
```

Module body (what `f2.run` does, in the order of the file): quick warp as F1 (form `$0AD4` = 1, `$0642` = `$01`, banner dismissed with A pulses, 300 settle frames), then three trials of 8 frames each on the player actor (slot `$1000`), forces written at every frame end:

- `T0_control`: no write; the idle loop shows the facing animation (`$28` = 1, idle north).
- `T2_setaddr`: `$08 = $24 = 0`, `$28 = 0`, `$2A = 0`, `$7F:1006` (`$7F:0006,X` of the slot) = original table pointer (`$8000`) + `2 * $4B` = `$8096`. Row 0 of that table is the word at `$0E:8096`, which is `$86AE`.
- `T1_index`: `$08 = $24 = 0`, `$28 = $4B`, `$2A = 0`, table pointer restored to `$8000`.

T2 runs directly after the control so that a metasprite pointer equal to group + 4 of the set cannot be a leftover of an earlier trial. At the last force frame of each trial the module reads the metasprite pointer, the live list (table word of the live registers), the group header and sub-sprites from the ROM, the OAM rows inside the crop `(88, 56, 128, 112)`, and compares part by part: expected position = host screen position (`$14` - `$068A`, `$16` - `$068E`) - left extent (header byte 0) + part x, and top extent (header byte 2) + part y; size; H flip (tile word bit 14); palette (bits 9-11); priority (bits 12-13). The offset between OAM and formula is voted from the control and also voted again per trial. It writes `F2_oam.txt`, three crops and a sheet. The full Lua source is in the module file (verbatim, hash above); the exact `uaa` counter is an exec callback on ROM offset 248405 (the first instruction of `UpdateActorAnimation`) that counts only calls with X = `$1000`.

An earlier run of the same module, with the order T0, T1, T2 and without the `UpdateActorAnimation` counter, gave the same OAM; it was repeated in the order above because in that order a stale pointer could not be told from a fresh one (T1 and T2 end on the same group). Its file `raw/F2_oam.txt` was overwritten by the final run.
