## Static prelude

`harness/w1e_static.py` (read only; output `raw/W1e_static.md`) lists every tagged instruction whose operand names an address of the watch (an indexed form counts by its base; COP operands are skipped). Static sites per watch (hit column = hit at run time): `$0B14/15` 0 (0), `$0648/49` 33 (8), `$090E-$0911` 2 (2), `$09BA-$09BD` 6 (4), `$09BE-$09C5` 6 (5), `$0200-$02FF` 5 (4), `$09EC/$09ED` 113 (0 in the main run; the `_dm` run covers it). Runtime sites that the static list did not contain: `InitSystemVariables+54` (171642, the `wram-init` table store, for `$0B14` and `$0648`), `DmaFixedByteFill+29` (171820, the boot-time WRAM zero fill), and for `$0200-$02FF` the `QuintetLzDecompress` stores/reads (164483, 164528, 164548, 164552) and the `SortActors_BuildFinalList` `PHA`/`PLA`/`PLY` (247540-247542; they reach the page through the stack pointer).

Static answers (read from the code before the runs):

- `$0B14`: named only by the `wram-init < $0B14, #$003C >` table entry (`system_init.asm:236`); no instruction names `$0B14` or `$0B15` as an operand.
- `gfxCacheIdxA` (`$0648`, word): 31 store sites write it (`ExecuteSceneTransition` 252551 stores `$0000`; 30 other sites in actor, cutscene, title and `StatueRewardEntry` (52853) code store a transition word); two instructions read it, `ScreenExitTransition` (252603, `LDA $gfxCacheIdxA`, the low byte is the exit type) and `ScreenEnterTransition` (253074, `LDA $gfxCacheIdxA+1`, the high byte is the enter type). `ExecuteSceneTransition` clears `gfxCacheIdxA` / `gfxCacheIdxB` at 252545-252551 after the enter transition and before the next read. The init `$0404` is stored by `wram-init < $gfxCacheIdxA, #$0404 >` (`system_init.asm:227`).
- `$090E/$0910`: two stores (`ReadMenuSelection`, 256574 and 256593) and no read. 13 sprite files carry `sprite-part < #01, ..., #$090E >`; the sprite decomposer reads bytes 5-6 of each 7-byte sub-sprite as the tile/attribute word (`sprite_composition.asm:538`), so that word is an OAM tile/attribute value, not a WRAM reference.
- `$09BA-$09BD` and `$09BE-$09C5`: the `SystemInit` stores at 32895-32913 (`system_core.asm:201-207`). `slopeCurvePtrA` (`$09BA`) is read by `ApplySlopeCurveNegEW` (177572) and `ApplySlopeCurvePosEW` (177604), `slopeCurvePtrB` (`$09BC`) by the two NS routines (177642, 177670), `decelCurvePtr` (`$09C2`) by `ReadDecelerationStep` (177932) and `ReadDecelerationStepNS` (178091); all are direct `ADC $addr` operands. No instruction names `$09BE`, `$09C0` or `$09C4` other than the stores.
- `$0200-$02FF`: `QuintetLzDecompress` uses it as the dictionary (`QuintetLzDecompress.asm:57`, 164474 `LDX #$0200`); it is also the first half of the depth-sort bucket array that `ClearActorRenderList` zeroes (`$0200-$03FE`, 252010) and `SortActors_BuildFinalList` consumes (a `PHA` over each popped bucket word). The 9 `JSL QuintetLzDecompress` sites are 39344 (the `Decompress` COP, which calls `ClearActorRenderList` itself at 39348) and 165180, 165284, 165359, 165756, 166062, 166218, 166933, 167026 (`scene_script.asm`). `ClearActorRenderList` is called from `ClearSceneState` (253529, phase 3 step 12, after the scene loads), twice by `OpenInventoryScreen` (191972, 192133) and by the `Decompress` COP (39348).
- The `bitmap < start, end, page, @gfx, mode >` command is opcode `$03` (`SceneCmd_LoadBgTiles`, `scene_script.asm:291`); mode 3 jumps to `Load4bppPage` (the only route to site 165284, the compressed-pointer path of that routine). The shipped `scene_meta.asm` has 319 `bitmap` commands with modes 0 (255), 1 (62) and 2 (2) and none with mode 3, so 165284 cannot run with the shipped data. Site 166218 is the compressed path of `DmaLowVramTileset` (reached from `SceneCmd_LoadLayerMaps` at 165943 when the layer flags are zero after a source-cache hit and the stream pointer is nonzero); it did not run.

```lua
-- description: W1 address census, batch e (unknown readers): $0B14, $0648, $090E/$0910, $09BA-$09C5, $0200-$02FF (decompressor dictionary vs depth-sort buckets), with exec marks and an ordering probe.
-- requires: mesen_kit, iog_kit, gaia_kit, w1d_kit
--
-- Use:  includes = {"gaia_kit", "a_census", "a_actors", "w1d_kit", "w1e_kit"}
--         local h = w1e.startE{logCap=60}
--         acen.run{..., final=function() return h.rowsE() end}
--
-- The census itself is w1d.start (kit/lib/w1d_kit.lua): every hit is keyed "<watch> <read|write> <K:PC>" (PC = the address AFTER the accessing
-- instruction), with count, scenes, addresses, values, and for reads the K:PC of the last write seen on the same byte ("init" = none seen in this run).
-- This module adds the watch list and exec marks of batch e and the ORDERING probe for the decompressor / depth-sort question:
--   at the entry of each `JSL QuintetLzDecompress` call site the caller is "pending"; ClearActorRenderList clears the pending callers (outcome "cleared first");
--   SortActorsByDepth marks the pending callers "sort first" (a sort ran before any clear; the sample keeps the frame, the scene and the frames since the
--   call) and the caller stays pending until the clear arrives (frames to the late clear are recorded).
--   At the entry of SortActors_BuildFinalList (the bucket array must be all zero there) the 256 words $0200-$03FE are scanned: a nonzero word is garbage that
--   phase 1 would chain.
w1e = w1e or {}

local function exec(off, fn)
  emu.addMemoryCallback(fn, emu.callbackType.exec, off, off, emu.cpuType.snes, emu.memType.snesPrgRom)
end

-- ROM offsets (decimal; ROM O; the `; {n}` tags of extract:lt output)
w1e.OFF = {
  QuintetLzDecompress = 164464,
  ClearActorRenderList = 252010,
  SortActorsByDepth = 247295,
  BuildFinalList = 247451,
  ReadMenuSelection = 256554,
}
-- the JSL QuintetLzDecompress call sites: the Decompress COP (cop_handlers_vram) and the 8 scene_script sites
w1e.CALLERS = {
  ["COP#51 Decompress"] = 39344,
  ["scene_script 165180"] = 165180, ["scene_script 165284"] = 165284, ["scene_script 165359"] = 165359, ["scene_script 165756"] = 165756,
  ["scene_script 166062"] = 166062, ["scene_script 166218"] = 166218, ["scene_script 166933"] = 166933, ["scene_script 167026"] = 167026,
}

w1e.batchE = {

-- ordering probe state
w1e.O = nil
function w1e.order()
  local O = { callers = {}, pending = {}, sorts = 0, clears = 0, builds = 0, dirtyBuilds = 0, dirtySamples = {}, nzHist = {}, decCalls = 0, overlap = 0 }
  w1e.O = O
  local function frame() return emu.getState()["frameCount"] end
  for name, off in pairs(w1e.CALLERS) do
    local c = { name = name, off = off, n = 0, clearedFirst = 0, sortFirst = 0, samples = {}, lateClear = {}, scenes = {} }
    O.callers[name] = c
    exec(off, function()
      c.n = c.n + 1
      O.decCalls = O.decCalls + 1
      local sc = kit.r16(0x0644)
      c.scenes[sc] = (c.scenes[sc] or 0) + 1
      if O.pending[name] then O.overlap = O.overlap + 1; c.superseded = (c.superseded or 0) + 1 end   -- the same site called again before any clear or sort
      O.pending[name] = { f0 = frame(), sc = sc, sortSeen = false }
    end)
  end
  exec(w1e.OFF.ClearActorRenderList, function()
    O.clears = O.clears + 1
    local f = frame()
    for name, p in pairs(O.pending) do
      local c = O.callers[name]
      if p.sortSeen then
        if #c.lateClear < 12 then c.lateClear[#c.lateClear + 1] = string.format("f%d sc=%02X +%d frames", p.f0, p.sc, f - p.f0) end
      else
        c.clearedFirst = c.clearedFirst + 1
      end
      O.pending[name] = nil
    end
  end)
  exec(w1e.OFF.SortActorsByDepth, function()
    O.sorts = O.sorts + 1
    local f = frame()
    for name, p in pairs(O.pending) do
      if not p.sortSeen then
        p.sortSeen = true
        local c = O.callers[name]
        c.sortFirst = c.sortFirst + 1
        if #c.samples < 12 then c.samples[#c.samples + 1] = string.format("call f%d sc=%02X, first sort at f%d (+%d)", p.f0, p.sc, f, f - p.f0) end
      end
    end
  end)
  exec(w1e.OFF.BuildFinalList, function()
    O.builds = O.builds + 1
    local nz, nz0 = 0, 0
    for a = 0x0200, 0x03FE, 2 do
      if kit.r16(a) ~= 0 then
        nz = nz + 1
        if a < 0x0300 then nz0 = nz0 + 1 end
      end
    end
    local b = (nz == 0) and "0" or ((nz <= 8) and "1-8" or ((nz <= 64) and "9-64" or "65-256"))
    O.nzHist[b] = (O.nzHist[b] or 0) + 1
    if nz > 0 then
      O.dirtyBuilds = O.dirtyBuilds + 1
      if #O.dirtySamples < 12 then
        local pend = {}
        for name, _ in pairs(O.pending) do pend[#pend + 1] = name end
        table.sort(pend)
        O.dirtySamples[#O.dirtySamples + 1] = string.format("f%d sc=%02X nzWords=%d (in $0200-$02FF %d) pending=[%s]", frame(), kit.r16(0x0644), nz, nz0, table.concat(pend, ","))
      end
    end
  end)
end

function w1e.orderRows()
  local O = w1e.O
  if not O then return nil end
  local cs = {}
  for name, c in pairs(O.callers) do
    local sc = {}
    for k, v in pairs(c.scenes) do sc[#sc + 1] = { k, v } end
    table.sort(sc, function(x, y) return x[1] < y[1] end)
    cs[#cs + 1] = { name = name, off = c.off, n = c.n, clearedFirst = c.clearedFirst, sortFirst = c.sortFirst, superseded = c.superseded or 0, samples = c.samples, lateClear = c.lateClear, scenes = sc }
  end
  table.sort(cs, function(x, y) return x.off < y.off end)
  local hist = {}
  for k, v in pairs(O.nzHist) do hist[#hist + 1] = { k, v } end
  table.sort(hist, function(x, y) return x[1] < y[1] end)
  local pend = {}
  for name, p in pairs(O.pending) do pend[#pend + 1] = string.format("%s call f%d sc=%02X sortSeen=%s", name, p.f0, p.sc, tostring(p.sortSeen)) end
  table.sort(pend)
  return { callers = cs, sorts = O.sorts, clears = O.clears, builds = O.builds, dirtyBuilds = O.dirtyBuilds, dirtySamples = O.dirtySamples, nzHist = hist,
           decCalls = O.decCalls, overlap = O.overlap, pendingAtEnd = pend }
end

-- w1e.startE{ publishEvery = 600, logCap = 60, win0200 = true (watch only $0200-$021F instead of the whole page), extra = { {name=,lo=,hi=,ctx=} ... } (additional watches), kinds = { ["name"] = {"read"} } }
function w1e.startE(o)
  o = o or {}
  local cfg = { watch = {}, exec = {}, probes = {}, nmi = w1e.batchE.nmi, control = true, logCap = o.logCap, publishEvery = o.publishEvery }
  for _, w in ipairs(w1e.batchE.watch) do
    local kinds = o.kinds and o.kinds[w.name]
    if o.win0200 and w.name == "0200-02FF" then   -- narrow window ($0200-$021F): the full page costs ~250 callbacks per depth sort
      local c = {}
      for k, v in pairs(w) do c[k] = v end
      c.name = "0200-021F"; c.hi = 0x021F
      w = c
    end
    if kinds then
      local c = {}
      for k, v in pairs(w) do c[k] = v end
      c.kinds = kinds
      w = c
    end
    cfg.watch[#cfg.watch + 1] = w
  end
  for _, w in ipairs(o.extra or {}) do cfg.watch[#cfg.watch + 1] = w end   -- extra watches (the displayModeFlags run)
  for k, v in pairs(w1e.batchE.exec) do cfg.exec[k] = v end
  for k, v in pairs(o.extraExec or {}) do cfg.exec[k] = v end
  local h = w1d.start(cfg)
  w1e.order()
  function h.rowsE()
    local r = h.rows()
    r.order = w1e.orderRows()
    return r
  end
  return h
end
```

## Positive control

- Write control: every run watches `INC $36` (the frame parity counter, written by the NMI handler at `$80:8381`). Total `$36` writes 90,329; NMI exec control (exec mark on 33528) 90,325. Per run the two agree within 1 (the write control counts the callback of the frame in progress); the boot run has 639 against 638, `natural_fr10` 18,847 against 18,847. Every one of the 54 runs fired the control, so no result is downgraded by a silent watch.
- Per-address controls: the exec marks of the batch (below, "Exec marks") fire where the code ran, e.g. `ExecuteSceneTransition_clear_gfxCacheIdxA` 108 times and the 216 byte writes recorded at `$0648/$0649` (108 words); `SortActorsByDepth` 90,430 and `BuildFinalList` 90,430 against 125 clears; `ApplySlopeCurve*EW` 68 + 23 calls and the 136 + 46 byte reads of `$09BA/$09BB`.
- Absence watches (`$0B14`, `$090E/$0910` reads, `$09BE/$09C0/$09C4`) use the same callback engine as the watches that did record reads in the same sessions, so a missing hit means that no instruction on the executed paths read the byte.

## Observations

1. `$0B14/$0B15` receives only the boot-time store (`$003C`, frame 3 of the cold boot) and the boot-time zero fill (frame 0). No read in 54 sessions and 112,358 frames, and no instruction names it statically.
2. `gfxCacheIdxA` (`$0648/$0649`) is a transition-parameter word: `ScreenExitTransition` reads the low byte (exit type: `00` 104, `01` 3, `02` 1) and `ScreenEnterTransition` the high byte (enter type: `00` 106, `02` 1); 108 transitions, each clearing the word at 252551 after the enter transition ran.
3. The boot value `$0404` (the `wram-init` entry) is never read: in the cold boot the clear at 252551 first runs at frame 26, before the first enter read (frame 85) and the first exit read (frame 204); all 5 boot reads return `00` and pair with 252551; no read of any session pairs with 171642.
4. Eight cancel events of the world-map menu (`ReadMenuSelection`, scene `FE`) wrote `$090E = $6D60` and `$0910 = $6DE0` (two values, 8 runs each). Nothing read `$090E-$0911` in any session, including the 11-session `_dm` run.
5. `(tile AND $03FF) x 8 + $6000` is the VRAM word address of a 2bpp tile with the BG3 character base `$6000` (8 words per tile); `$6D60` is tile `$1AC`, `$6DE0` tile `$1BC` (16 tiles apart). The sprite decomposer reads bytes 5-6 of each 7-byte sub-sprite as the tile/attribute word (`sprite_composition.asm:538`), so the `#$090E` last word of the 13 `sprite-part` records is a tile/attribute value that is copied into OAM, not a read of the WRAM word (static; no run decomposed those records with a watch on the word).
6. `displayModeFlags` bit 0 (set by the menu on every redraw) is consumed by `Bg3TilemapVramDma` (176184/176190) and cleared by the `TRB` at 176262; the `_dm` run (`$09EC/$09ED` watch) shows the set/consume/clear sequence (already VERIFIED-RUNTIME in C4).
7. `$09BA` is read by both EW slope routines (68 + 23 reads, values `$C384`), `$09C2` by `ReadDecelerationStep` (84 reads, value `$C3A4`); `$09BE`, `$09C0`, `$09C4` have no read in any session and no instruction names them other than the `SystemInit` stores. The NS routines never ran (0 executions of 177642, 177670, 178080).
8. `QuintetLzDecompress` ran 525 times (`COP #51` 14, `scene_script` sites 165180 x145, 165359 x25, 165756 x114, 166062 x149, 166933 x76, 167026 x2; 165284 and 166218 never). It fills `$0200-$02FF` (dictionary) on every call: 14,592 dictionary-fill stores and 125,284 + 197,618 copy/literal stores.
9. `ClearActorRenderList` ran 125 times: 14 right after the `Decompress` COP (scene `F7`, `warp_b2` 7 and `warp_credits` 7), 3 in `menu_inventory` (a session with no transition mark; `OpenInventoryScreen` holds both static call sites, 191972 and 192133), and 108 in the other sessions, which equals the 108 marks of the transition clear at 252551 in total (per session equal, except `natural_fr10` 17 clears against 18 marks and `e_n03_s3` 11 against 10; the per-session list is in the report).
10. Ordering probe: of 525 decompress calls, 380 were followed by a clear before any sort, 145 were followed by another call of the same site before any clear or sort (chained loads inside one scene setup; each chain ends in a clear), 0 were followed by a sort first. At every one of the 90,430 `SortActors_BuildFinalList` entries all 256 words `$0200-$03FE` were zero (0 dirty entries). The clear after the `Decompress` COP is the handler's own `JSL` (39348, 14 of 14).
11. Because `ClearSceneState` runs the scene loads (phase 2) before its own `ClearActorRenderList` (phase 3, 253529) and no sort runs inside a scene setup, every `scene_script` call site is followed by that clear; the two sites that never ran (165284: mode 3 never used by the shipped `bitmap` commands; 166218: compressed path of `DmaLowVramTileset`) are in the same sequence.
12. `ClearActorRenderList` is also called by `OpenInventoryScreen` (191972, 192133) and by the `Decompress` COP (39348). The shipped block note (`sprite_composition.asm:7`) and part note (`sprite_composition.asm:85`) list only scene setup and the inventory overlay; the `Decompress` COP is a third caller (spec `specs/W1-e_notes.json`).
13. `ReadMenuSelection`: the shipped comments call the values "OAM" data (`MenuSelectionHandler.asm:16`, `360-362`, `369`, `374`). The measured values equal the 2bpp CHR word address of the cursor tiles with a `$6000` character base; they are not OAM words, and the two stores are dead (observation 4).
