## Static prelude

- Actor slots are **84 x `$30` bytes** from `$1000` to `$1FBF`, not `$40` (the plan, line 196, and `docs/wram-memory-map.md:423` say `$40`). Evidence: the live enemy slots found by the runs were `$1210`, `$1240`, `$1450`; the extended-state tables are indexed by `slot - $1000` with `$30` bytes per actor (`docs/wram-memory-map.md:486`). The census filters writes with `0x1000 <= addr <= 0x1FBF`, `(addr - 0x1000) % 0x30`, field offsets `0x10..0x13` (a run with a `$40` stride recorded non-flag writes and was discarded; all numbers below are from the `$30` rerun).
- Fields: `+10` Flags10, `+12` Flags12, `+14`/`+16` X/Y, `+00` entry pointer (bank byte at `+02`), `+08` wait, `+0E` OAM xor word.
- The census records, per write: effective address, old value, new value, the program counter after the accessing instruction (`PC` minus the instruction length gives the opcode address), the slot, the scene, and whether the slot is the player (`$1000`). `harness/decode_flag_census.py` decodes each K:PC against the ROM (opcode, operand, nearest label with `+offset`) and attributes `file:line` of the extracted block that contains it. The `file:line` in the tables is the **block start** in `extracted/`, not the instruction line.
- A1 counts are **value-changing** writes only (`stats.writeChanges`, for example 4,252 of 150,294 flag-field writes in `castoth_will`): a `TSB` on a bit that is already set is not counted. The A2 file counts executions of the instruction (read side), so a site can show a higher number there (for example `dm3D_flayzer3+148`: 4 changing writes, 14 executions).
- Writes made by the engine's bulk routines (`InitActorPool`, `SpawnListAppend`, `CopyActorState`, `InitActorFromSceneData`, `SpawnAfter*`) are listed as "bulk": they store whole words, so the individual bit is only a side effect.

## Script

Verbatim Lua of every session (the exact `code` string sent to `run_script`, generated by `harness/scenario_a1_flag_census.py`) is saved in `raw/A1_A2_scripts_20261030.lua.txt`. The library it includes is `kit/lib/a_census.lua` (`acen.run{frames, writes, reads, bot, at, timeline, execs, sample, ...}`):

- a write callback on `0x1000-0x1FBF` that keeps only the `+10..+13` fields and emits one `W` line per change;
- a seeded input bot (`BASE_BOT`) that produces the same inputs on every run, and a `timeline` of scripted holds;
- `at[frame]` hooks for teleports and forced writes (`kit.w16`, never into low direct page);
- exec callbacks on named labels (resolved with `get_label_address`) to prove that a code path ran.

## Positive control

- `control36Writes` (writes to the frame-parity counter `$36`, written by NMI every frame) is non-zero and about equal to the frame count in every session (for example 3136 for 3317 frames in `mine_will`, 1225 for 1226 in `sc_npc_talk`): the write callback was alive for the whole run.
- Known writers appear: `InitActorFromSceneData` stores `$8508` into the player at every scene entry (17 scene entries); `PlayerCharacterDef+13` sets `$12 |= $0001` on the player exactly once per entry (17); `PlayerIdleEntry` sets and clears the player's `$0100` / `$0020` (see the `A2` file).
- Exec counters prove the ability paths ran: `mine_will_abil` `LaunchPsychoDash` 1, `PsychoDashMain` 1, `LaunchSpinDash` 1, `SpinDashRelease` 1, `AttackInit` 6; `mine_freedan_abil` `LaunchAuraBarrier` 2, `AuraBarrierMain` 2, `LaunchDarkFriar` 1, `DarkFriarMain` 1; `sc_npc_talk` `GlobalAmbientTargetInRange` 4.
- The first two ability runs fired nothing: the charge needs 40 + 120 frames (Will) or 40 + 100 (Freedan), and the holds were too short. Fixed and re-run; only the fixed runs are used.

## Coverage

14 sessions, 24,190 frames (sum of the table), ROM O only, scenes `$01`, `$02`, `$08`, `$29`, `$3E`, `$3F`; characters Will, Freedan, Shadow; no other ROM. **Not reached** (any absence claim below is limited by this): no enemy killed by the player (so no `$0400` defeat flag write, no drop pickup, no stat pickup), no Dark Space warp (the South Cape portal never became usable: 8 positions x 3 Up presses, 0 `DarkSpaceEnterWarp` calls), no `ForcedWalk*` / `SyncPlayerToCamera` / `StartForcedWalk` call (`mine_exit_warp` left the scene by a normal warp), no ramp (`ramps.asm` writers), no Psycho Slider glide (`slider_glide.asm`), no Earthquaker, no `ToggleActorVisibilityFlag` helper (`sp5B` rooms), no `InteractionDamage_NPCChat` (the `$0700` write), no sign / door / chest talk.

## Observations (writes, decimal counts are executions in all sessions)

1. `$10` bit 3 (`$0008`): set at spawn (`InitActorFromSceneData` 17, `CopyActorState` 163), by `HitStaggerMain+14` (19, all on enemies: 16 in Castoth) and by `dm3D_flayzer3` toggles (3); cleared by `dm3D_flayzer3` (3), `SpawnListAppend` (116), `InitActorPool` (68). The player's `$0008` was never written outside spawn (A3 X3 forces it).
2. `$10` bit 9 (`$0200`) on the **player**: `RangedSetForceY+20` sets (8, the Freedan/Shadow ranged lunge), `StopPlayerOnDeath+21` sets (3, all three deaths), `AuraBarrierMain+5` sets (2) and `AuraBarrierEnd+5` clears (2), `SpinDashMain+98` sets (1), `RunAttackFlagSetup+5` sets (1) and `RunAttackCleanup+5` clears (1), `SpinDashAbort+5` clears (1), `RangedAttackEast+13` clears (8).
