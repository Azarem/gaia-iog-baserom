### Details per question

**OQ-I059-4.** Within the first frame of the scene the order is: the controller's first pass adds `$FFE0` to `$B8` (which is 0), then Init stores `$0400`. The first effective value is `$0400` (read at 238469 on the second pass, n=173). 44 `ADC` passes run (n=161, then n=173 to n=257 in 42 steps of 2 ticks); the last add leaves `$B8` = `$54` (84), not about `$34`: 43 effective deltas sum to -940, and the first one that Init overwrites is -32, which explains the hand-computed -970 (-972 for 44).

**OQ-I041-2.** `M7A` = `M7D` = 32767 x cos / divisor in 8.8 fixed point. `$B8` = `$80` gives 255 (1:1); a larger divisor shrinks `M7A`, so the picture is zoomed in (`$0400` gives 31, `$24E` gives 55 and the screenshot is strongly zoomed). With `$B6` = `$039A`, `$B8` = `$AE`: `M7A` falls from 188 at the first line to 33 at the last, so the zoom grows towards the bottom. Increasing `$BC` rotates the map clockwise on the screen (`$BC` = +32: `M7B` +149, `M7C` -149; `$BC` = -32: the signs swap). The Angkor vision (`$C0`) raises `$B8` from `$1F` to `$80` while `$BC` runs `$0135` to `$0200`; its tables match the formula within 4.5%, the prologue (`$8C`) within 0.8%.

**OQ-I041-3.** In `$FE`, `$8C`, `$59` and `$C0`, nothing writes `$7E7000-$8FFF` after the first table fill: the census attributes every foreign write in the scene to the decompressor (`82:82AF` / `82:82CF`) before the fill or to the next scene's load after the scene has left. `IrisCircleEffect` writes `$8D00-$8E23`, outside the three tables (`$7000`, `$7800`, `$8000`, 673 bytes each). The spawner list above is the coverage: the four scenes are the only ones that run `Mode7PerspectiveUpdate`.

**OQ-I041-4.** All four overflow labels are taken: the menu trip takes `ov1` 695 and `ov2` 528 times; the scripted rotation takes all four (`ov1` 622, `ov2` 384, `ov3` 1,053, `ov4` 423). The table values at the two lines an overflow touches have second differences no larger than on other lines (A: 3 and 3, B: 2 and 2), so the unhalved fraction byte does not leave a visible step above rounding noise (a 1-line, 1-count step in a smooth 224-line ramp).

**OQ-I058-1.** The boundary row is the end of the second BGMODE count (127 + `$18` + 2 x step lines of Mode 7, then `$09`). Below it the screen is Mode 1 with BG3 priority; the COLDATA table alternates `$FF` and `$01` data bytes (`$01` selects no colour plane), so the fixed colour is white on every line; colour math subtracts it from BG1 and the backdrop, which gives a black panel carrying the BG3 text. The second count is `$18` + 2 per frame (`$1A` at route+1 for table A, `$68` from route+40 on); the boundary row 151 + 2 x step reaches row 224 at step 37, and the route+42 screenshot is all Mode 7 (BGMODE `$07`). The screenshot frame has a 7-line top offset, so the boundary looks like row 158 on the PNG.

**CL-10.** `M7SEL` is written `$80` once (n=161, rom 239945) and stays. Past the plane (view rotated by `$BC` = `$0100`): black with `$80`, the repeating map with `$00`, black with `$C0`. `$80` and `$C0` look identical because tile 0 also renders black (CGRAM entry 0 is 0), so the pixels do not separate "transparent" from "tile 0 fill"; the emulator state reports `fillWithTile0` = false for `$80`. The three cutscene scenes write `$00` once each.

**OQ-I056-8.** The pan targets of all 35 scene ids settle at the words of their table entry (the cursor `$0D92` and slot word `$0D74` are poked; `DiaryCameraPan` moves `cameraTargetX/Y` `$06BE/$06C2` there).
