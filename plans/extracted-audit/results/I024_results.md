| Q3 | **F** | (a) **Layout**: the parameter is one 16-bit script word: low byte packed (high nibble N = total items when there are two columns, low nibble C = first-column items; N = 0 means one column of C items), high byte = first text row. The old text said "rows x columns / items per row" and "SP+5 = row". In the handler SP+1/2 = selection, SP+3 = packed, SP+4 = row (+2 inside `DrawMenuCursor`). (b) **Navigation is column-based**: Down wraps within its own column, Up from item 0 wraps to the LAST item and from the top of column 2 goes to the bottom of column 1 (asymmetric), Left and Right both toggle the column, SFX only when the column changed. "L/R page" is a two-column layout, "page" is a column. (c) **Buttons**: confirm is bit `$8000` (the A button after the remap), cancel `$4000` (B); Start is not accepted; "L/R" are D-pad Left/Right. (e) The initial selection is always 0; the old comment put "initial selection" on the blink-counter store. (f) Blink period is 32 frames (bit 4 of `$0994`; 16 lit, 16 dim), not "16-frame cycle". (g) Confirm does NOT restore the tiles under the cursor: the lit cursor stays drawn; only cancel restores via `ReadMenuSelection`. The `$0A/$0C` push/pop around the confirm SFX is a no-op. (h) `ReadMenuSelection` stores (tile and `$03FF`) x 8 + `$6000` = the VRAM word address of that glyph in the font at `$6000`, not OAM sprite data; no code reads `$090E/$0910` (see OQ-I024-3). (j) Cursor offset = ((((first row + r) x 2 + `$0980`) x 32 + `$097E`) x 2) + column offset (`$18` bytes = 12 tiles for column 2) into `bg3TilemapBuffer`/`bg3TilemapRow1`; sets `displayModeFlags` bit 0 | PROPOSED (all in the prepared notes file) |
